## 首版交付目标

一个新应用或已有应用完成接入后，用户可以从应用内发起任务，也可以从原有 Agent 发起任务，在明确授权范围内使用应用材料和方法，获得产出或应用成果。遇到中断时，应能核对本应用操作的影响并决定如何继续。

目标包含保存时，以应用保存成功并可读回为完成条件。目标仅为分析时，以产出可见且能继续使用为完成条件。进程正常退出或模型返回文本，不能单独证明业务任务已经完成。

## 两种使用场景与职责差异

| 事项 | A 在应用中调用自己的 Agent | B 在原有 Agent 中操作应用 |
| --- | --- | --- |
| 发起入口 | 应用页面、操作按钮或对话区 | 用户已有 Agent 宿主 |
| 应用需要接通 | 会话输入输出、必要状态和批准界面，以及获准数据与方法 | 受保护的 MCP 应用能力服务、连接说明、业务结果查询或展示 |
| 对话与 Agent 选择 | 应用适配原生引擎，并由用户在应用内选择 | 原有宿主管理，应用不必再建聊天窗口或选择器 |
| 工具执行 | 应用原业务接口授权、执行、返回结果 | 同一业务 owner 授权、执行、返回结果 |
| 停止和恢复 | 控制本应用管理的会话，并区分在途业务影响 | 按实际支持取消本应用调用，原宿主控制整个对话；应用不接管其他宿主任务 |
| 成功出口 | 产出交付应用；需要保存时有原应用成果及必要读回 | 工具结果交付原宿主；有业务操作时原应用成果可见 |

两种入口的原生执行权限信任边界不同。A 的参考适配需落实其管理的执行限制；B 的原生文件、终端和其他工具权限由原宿主与用户管理。应用 MCP 服务仍检查自己的每次调用，但不能把服务授权声称为对整个原有 Agent 的沙箱。

## 产品组成与交付方式

| 组成 | 直接使用者 | 用途 |
| --- | --- | --- |
| 应用侧接入包、接入说明和示例 | 开发者或辅助其开发的 AI 编码工具 | 接通连接、会话、任务、事件和业务工具，复用统一的接入规则 |
| 本机连接与执行能力 | 应用及最终用户 | A 发现和启动受支持 Agent；B 沿已有宿主连接应用能力服务；各自在所属边界管理授权和执行 |
| 可复用的基础交互 | 开发者和最终用户 | A 提供连接、Agent 选择和执行界面；B 复用原宿主交互，并提供应用授权和成果入口 |

A 的本机执行能力可以由应用随附，也可以由用户安装共享连接器。B 可直接使用原有宿主支持的 MCP 连接，不强制再启动一个负责整个 Agent 的 daemon。需要的桥接复用同一应用能力定义和业务接口；SDK、本机接口和打包方式的详细设计留到技术设计阶段。

新项目与已有项目都可以采用适合自身运行环境的接入方式；不能机械规定新项目只能嵌入、旧项目只能调用独立服务。

## 首版核心功能

| 功能 | 首版应提供的行为 | 成功判据 |
| --- | --- | --- |
| Agent 发现与可用性检查 | 列出受支持的本机 Agent，区分未安装、需登录、版本不兼容、未验证、可用与暂不可用；提供明确处理入口 | 找到程序不被直接当作任务可执行；实际调用能力得到验证后才标为已验证可用 |
| 应用连接与授权 | 展示可核验的应用来源、申请的目录、材料和工具权限；用户可授权、查看和撤销 | 连接只对获准应用及范围生效，不能凭同在本机直接获得调用权 |
| Agent 与配置选择 | 选择引擎及其支持的模型和明确导入的指令、skills；显示实际应用的配置 | 选择生效且范围清晰，不修改用户原有个人配置，不隐性继承额外权限 |
| 应用上下文传递 | 应用提供当前对象、用户选择的材料和必要业务信息，并标明范围 | Agent 取得完成任务所需上下文，未授权资料不被自动加入 |
| 持续会话与任务发起 | 从业务按钮或对话发起任务，支持同会话追问；新建和恢复会话都有明确归属 | 同一任务上下文持续，不能混入其他应用、账号或引擎的会话 |
| 受控业务工具调用 | 应用声明可调用功能，业务执行前由应用再次校验身份、范围和业务条件；需要批准时展示具体操作 | Agent 能完成实际业务动作，无权、过期或越界请求被拒绝，且其他执行路径不能绕过限制 |
| 执行反馈与人工控制 | 展示进展、等待批准、等待补充、排队、错误与停止状态；支持停止和必要的用户回复 | 用户知道当前在做什么、是否需要自己操作；停止请求与实际停止结果分别呈现 |
| 结果保存与读回 | 区分生成内容、待保存内容和已保存业务结果；通过应用原有接口保存和读回 | 保存成功有应用权威读回依据，刷新应用后仍能找到目标成果 |
| 恢复、诊断与断开 | 处理断线、重启、登录失效、会话失效及不确定写入；允许断开应用授权 | 已发生的效果可核对，不把未知状态当失败后盲目重做；断开后不能继续获得新调用权限 |

表中的 Agent 发现、应用会话和完整流式反馈主要对应 A；B 的 Agent 选择、个人配置、持续对话与整体执行控制由原宿主管理。两者都需要获准数据、方法执行、真实结果和相应异常处理，但不能要求 B 为通过验收复制 A 的全部界面。

A 的基础交互可以由开发者复用，也可以按应用风格实现。自行实现界面时，必须保留目标能力需要的权限信息、执行状态和恢复操作，不能用聊天输入框代替已承诺的业务操作。

首版不要求每个任务再做一次付费探测。安装和配置检查应尽量不调用模型；需要真实连通性测试时，由用户主动触发并说明可能消耗用量。引擎没有返回用量时显示未知，不能显示为零。

## 开发者和最终用户的职责

| 事项 | 开发者需要完成 | 最终用户需要完成 |
| --- | --- | --- |
| 应用接入 | 集成接入能力，声明应用身份和可核验来源 | 确认连接的是预期应用 |
| Agent 环境 | A 提供引擎检测和修复；B 说明兼容宿主与应用服务连接方式 | A 在应用内选 Agent；B 在原宿主连接应用，分别按支持方式认证 |
| 上下文 | 定义从哪些应用对象取得材料，控制必要范围 | 选择本次使用的对象或材料，授权相应范围 |
| 业务工具 | 将现有业务功能暴露为受控工具，保留业务校验和存储 owner | 授权明确的操作范围，处理超出既有授权的请求 |
| 个性化配置 | A 支持有边界的配置选择；B 不接管原宿主个人配置 | 在对应应用或宿主选择所需配置，了解实际访问范围 |
| 执行和结果 | 接收状态和工具请求，保存并展示结果，处理恢复与重复请求 | 提供任务、必要补充和决定，查看结果并继续使用 |
| 运行故障 | 提供可理解的原因、诊断信息和恢复入口 | 重新登录、恢复连接或核对有待确认的操作 |

不要求最终用户编写工具定义、配置协议或复制认证令牌。首版建议不要求额外注册本产品的云端账号；接入应用原有账号与 Agent 自身认证仍分别处理。

## 新项目如何接入

以创建一个个人知识库为例。

1. **先定义应用内任务。** 开发者确定用户要完成“读取选中的论文、比较方法、保存阅读笔记”，明确材料从哪里来、结果放在哪里。
2. **定义必要业务功能。** 应用提供“读取选中材料”“创建或更新指定笔记”“读取已保存笔记”等功能，并继续负责访问控制和业务持久化。
3. **声明共同能力并接通所需入口。** 声明应用身份、来源、所需权限及方法。A 接通 Agent 会话与执行事件；B 将同一应用方法通过 MCP 提供给原有宿主，两者都要保留真实业务校验。
4. **提供对应使用入口。** A 在原业务页面提供任务和必要状态界面；B 提供 MCP 连接与授权说明，复用原宿主对话，不要求新增应用内聊天框。
5. **接通工具执行与结果回读。** 收到工具请求时，由应用校验身份与操作范围，再调用自己的业务接口。完成后返回真实操作结果，并读回已保存的笔记。
6. **交付完整安装和首次使用路径。** 说明运行应用、本机执行组件以及 Agent 环境分别如何获得；已有环境直接复用，缺少的部分才引导安装或登录。
7. **验证完整使用与异常场景。** 按本文完成标准检查持续对话、保存读回、权限拒绝、停止、重启恢复和重复请求等行为。

可以将这套接入说明交给 AI 编码工具辅助完成。生成代码或编译通过，只说明开发取得进展；开发者仍需在实际应用中验证最终用户路径。

## 已有项目如何接入

已有项目沿用同一套接入规则，重点是连接已有能力和数据。

1. **核实可扩展入口。** 确认有可修改源码、插件机制，或足以增加授权、任务入口和业务调用的接口。仅有数据导出能力时，可以先提供材料分析，但尚不等于完成应用内回写。
2. **选择一个现有业务任务。** 例如知识库已经能保存笔记，就先接“选中材料后生成并保存笔记”，保持目标可观察。
3. **复用现有业务功能。** 将已有材料读取、笔记保存和查询能力接为工具；业务权限、校验、事务和数据库写入仍由原应用负责。
4. **补充所需入口。** A 在原页面增加连接设置、任务与状态；B 增加受保护的 MCP 应用能力服务及连接说明。按入口接通批准与结果，不要求整个应用改造成聊天产品。
5. **处理已有数据和失败语义。** 明确新增还是修改、结果属于哪个用户和对象、重复请求是否已执行、写入失败如何核对；不能让模型直接绕过原应用修改数据库。
6. **用真实旧数据验证原功能和新流程。** 验证 Agent 操作结果能够被原页面读取，并确认人工编辑、权限规则和其他关联业务继续成立。
7. **按原应用方式交付更新。** 由应用作者完成发布或安装更新，最终用户随后连接自己的 Agent，不需要重新开发应用。

没有可扩展入口的封闭应用，不承诺零修改接入。纯对话和只读分析可以独立构成完整目标；应用承诺了保存、修改等操作而尚未接通时，才应将对应操作记为部分接入，不能把对话结果当作已完成业务写入。

## 场景 A 最终用户完整使用流程

以下流程在新项目和已有项目完成 A 接入后相同。

### 第一步 打开应用中的 Agent 入口

用户从设置页或业务操作入口选择“连接本机 Agent”。界面说明连接后能处理哪些材料、执行哪些功能，以及结果保存到哪里。

连接器由应用随附且已运行时，无需再安装一份；需要共享连接器时，提供安装与启动入口。

### 第二步 检查本机环境

应用展示受支持的 Agent 及检测状态。已有可用环境直接选择；未安装、需登录或不兼容时，提示具体处理方法。

登录按原生引擎受支持方式完成。应用不要求用户把 Agent 的密钥或登录文件复制进业务表单，也不能将“检测到程序”误报为“真实请求已验证成功”。

### 第三步 确认应用授权

本机确认界面展示可核验的应用来源、申请的材料或目录范围，以及可执行的操作。用户可以同意、缩小范围或拒绝。

授权不能仅靠提示词约束。应用身份、上下文范围、业务工具权限和 Agent 原生文件、终端及网络权限必须真正生效。只能以更大权限运行的能力，不得偷偷启用。

所选 Agent 可能将材料交给外部模型服务处理时，应在授权与上下文说明中清楚表达。

### 第四步 选择 Agent 和工作配置

用户选择 Agent、受支持的模型，以及本次要加载的指令或 skills。界面显示哪些配置实际生效及其访问范围。

默认创建该应用专属会话。更换引擎、账号或关键工作范围时，应创建或选择对应的新会话；用户同意后可以传递必要上下文，但不能直接混用原生会话 ID。

### 第五步 在原业务页面发起任务

用户选中几篇论文，输入“比较它们的研究方法，整理成一份阅读笔记”，并确认材料范围与目标位置。

开发者可以设计专用按钮，也可以使用对话入口。任务上下文由应用明确提供，不能默认扫描整台电脑。

### 第六步 执行并按需与用户交互

用户看到执行进度和必要的工具操作摘要。Agent 缺少信息时提出具体问题；需要新权限或批准时，展示将操作的对象、动作和影响。

已授权的同一操作无需重复确认。例如用户发起任务时已经明确授权“将结果保存为指定目录下的新笔记”，相同范围内的保存不再增加重复审批。覆盖已有内容、扩大范围或执行其他未授权操作时，重新请求相应决定。

同一会话已有任务执行时，后续任务排队或由用户取消等待。不能并发向同一个原生会话写入互不协调的任务。

### 第七步 保存并展示结果

需要用户确认内容时，先展示待保存产出。获得所需授权后，应用调用原有保存接口，取得结果标识，再读回目标笔记。

保存成功后，界面展示笔记位置和可打开入口。生成成功但保存失败时，保留产出并说明原因，让用户修复后继续保存，避免为相同内容重新调用模型。

纯分析任务可在产出展示后结束，不强制保存到额外业务对象。目标包含保存时，“内容已生成”只是中间结果。

### 第八步 继续使用或下次恢复

用户可以继续追问或修改材料，也可以关闭应用。再次打开后，应用中的成果仍可读取；支持恢复时继续原应用会话。

原生会话已失效或不支持恢复时，明确说明，并由用户选择新建会话和是否传递必要上下文，不能声称原上下文完整保留。

### 第九步 停止或断开连接

任务运行中可以请求停止。界面先显示正在停止，确认终止后再显示已停止；正在发生的业务操作仍需返回结果或进入待核对状态。

停止不自动撤销已经成功保存的修改。界面照实列出已产生的影响；需要撤销时使用应用已有的撤销或恢复能力。

用户可以撤销该应用的连接与权限，阻止后续调用，并请求停止在途任务。断开连接不删除应用成果，也不应导致用户退出其他应用使用的原生 Agent 账号。

## 场景 B 最终用户完整使用流程

1. **取得应用连接信息。** 应用作者或插件提供受保护的 MCP 服务及连接说明；应用未接入时，先由作者完成接入，用户不能仅靠安装连接器控制任意软件。
2. **在原有 Agent 宿主中连接。** 用户添加服务并按支持方式认证，确认应用来源、可用资源和操作范围；Agent 的模型与个人配置仍由原宿主管理。
3. **在原宿主提出任务。** 例如“读取资料库最近的材料，生成并保存笔记”。Agent 通过明确的应用资源或方法取得对象范围，不假定能够自动读取应用当前 UI 选择。
4. **发现与调用获准方法。** 原宿主将应用可见方法交给 Agent。应用每次执行时重新校验身份、对象权限、参数、版本和必要批准，目录可见不等于自动获准任意执行。
5. **处理问题和批准。** 使用双方支持的宿主或应用交互通道。所需能力不受支持时明确拒绝或等待，不因缺少应用内聊天界面而默认批准。
6. **接收结果并查看应用成果。** 工具结果回到原宿主，应用按原业务查询或事件展示实际成果。应用无需接收原宿主全部消息或最终自然语言回答；已保存的成果可在应用中打开。
7. **处理失败和不确定效果。** 读回原应用操作状态后决定是否重试。该场景同样遵守取消不等于回滚、请求编号不等于幂等键的规则。
8. **继续或断开。** 用户在原宿主继续对话，也可撤销本应用服务访问。应用只控制自己的授权和操作，不删除原宿主对话或停止其他应用任务。

同一原宿主连接多个应用时，还要由宿主按用户批准的目的、材料范围与接收方控制跨服务披露。工具说明或返回内容不能诱导 Agent 把一个应用的私密材料作为另一个应用的参数发送出去。已有明确授权的跨服务任务不重复询问；宿主不支持此项控制时，应说明限制，不把该隐私隔离当成已提供能力。

后面的异常与结果规则对两种场景共同适用；对话与原生会话恢复由各自拥有它的应用或宿主负责。

## 任务过程与业务结果如何表达

执行进展与业务结果是不同信息，应同时如实展示。以下为产品表达，不要求新建两套业务状态机。

| 用户看到的情况 | 含义 | 接下来可以做什么 |
| --- | --- | --- |
| 正在排队或执行 | 请求已接受，尚未完成 | 查看进度、取消等待或请求停止 |
| 等待补充或批准 | 需要用户的具体信息或授权 | 回复、批准、拒绝或停止 |
| 内容已生成，尚未保存 | 产出存在，业务写入尚未完成 | 查看、修改或批准保存 |
| 已保存，可打开 | 原应用确认结果持久化并读回成功 | 打开成果、继续追问或后续编辑 |
| 执行失败，影响已知 | 某一步失败，已发生和未发生的操作明确 | 按失败步骤修复和继续 |
| 结果待核对 | 断线或中断导致无法确认写入是否发生 | 查询应用权威状态后再决定是否重试 |
| 正在停止或已停止 | 分别表示停止请求处理中和已确认停止 | 查看已发生影响，必要时用应用恢复能力处理 |

## 关键异常流程

| 异常 | 需要表现的行为 | 禁止的错误处理 |
| --- | --- | --- |
| 未安装、登录失效或版本不兼容 | 给出具体原因和修复入口；恢复后检查是否可继续 | 无提示地更换用户选定的引擎、账号或模型 |
| 额度不足、限流或模型暂不可用 | 保留任务和已生成结果，说明是否可等待或由用户重试 | 隐性切换付费来源、无界重试或将失败显示为完成 |
| 本机连接断开或应用重启 | 使用原任务和会话归属重新核对进展与成果 | 重连后直接新建同一任务，造成重复操作 |
| 保存请求发出后响应丢失 | 应用按请求标识和业务记录确认是否已执行；不确定时保持待核对 | 将超时等同于没有写入，盲目重做 |
| 用户拒绝或撤销权限 | 停止相应调用，报告已发生影响；后续步骤重新授权 | 通过 shell、文件操作或其他工具绕过拒绝 |
| 原生会话失效 | 说明失效，提供受控的新建会话和上下文接续方式 | 静默重置，并向用户声称会话完整恢复 |
| 生成成功而保存失败 | 保留产出，修复保存条件后继续保存与读回 | 只展示成功，或强迫用户重新生成 |
| 重复点击或相同工具请求重放 | 原业务 owner 按已验证幂等、唯一或版本约束，或可信稳定业务关联，原子返回已有结果或拒绝重复；B 的宿主重发同样受约束 | 将新 RPC ID 当作新业务意图，响应丢失后自动换业务键，或缺少防重保障仍执行业务写入 |
| 其他服务诱导披露材料 | 原宿主检查发往目标服务的参数是否符合用户批准的数据范围、目的和接收方；不具备此能力时明确不提供该隔离承诺 | 将连接多个服务视为允许互传全部材料，或把披露控制推给无法识别来源的目标应用 |

## 必须保留的产品约束

1. 应用是业务身份、权限、事务和结果的权威所有者。本机连接成功不能替代业务授权。
2. A 的会话绑定应用、用户范围、工作区、引擎和对应认证配置。B 的原对话由原宿主管理，应用校验每次自身调用的授权范围，不强制获取全部原生会话信息。原生历史都由引擎持有，不能凭裸会话 ID 接入其他主体上下文。
3. 多个应用不默认共享授权、私密材料或业务结果。B 可由用户在同一宿主对话使用多个应用，但跨服务上下文聚合与披露归原宿主管理，连接本身不构成互传许可；需按已授权目的、数据范围和接收方控制方法参数，工具描述与结果不能扩大该范围。应用服务权限不证明跨服务隔离，宿主不能落实时明确不提供该隐私承诺。
4. A 需落实其管理的原生执行限制；B 的原生权限由原宿主与用户控制。应用工具自身授权都要执行，不能把 MCP 服务权限冒充全机隔离；必要的整体限制不能成立时，明确不支持对应安全承诺，不隐性扩大权限。
5. 被准入的写方法保证同一业务请求不重复产生效果，由原 owner 按已验证业务约束或可信稳定业务关联识别并原子复用结果或拒绝重放；A、B 的新 RPC ID 与并发重发不能绕过。无法满足时，相应写入能力不通过准入、仍属未闭环，不能只禁己方自动重试便声称安全。效果未知先核对，能否查询或安全重试分别声明。
6. 业务保存、撤销和恢复由应用自己的机制负责；停止执行不是撤销历史写入。
7. 个性化配置按来源和权限选择加载，不覆写个人原文件，不将个人凭证复制到业务应用或诊断输出。
8. 应用已有的人工操作、权限规则和数据读取路径继续成立。新功能不能绕开原有业务约束。

## 首版完成标准

使用一个不依赖青凝服务器的独立个人知识库，按以下完整出口验证；A、B 分别验收，不能只通过其中一条便声称两种入口都可用：

1. 从首次启动开始，用户能够理解并完成所需安装、连接和授权。
2. 选择一个正式支持的本机 Agent，连续两轮对话，实际使用用户选定的应用材料。
3. 经相应授权调用应用工具，生成并保存阅读笔记，应用读取并打开同一结果。
4. 刷新或重启后结果仍存在；A 在原生引擎支持恢复时恢复正确会话，B 在原宿主的实际支持范围内继续对话，不伪造应用控制的恢复能力。
5. A 验证受管理会话及执行范围隔离；B 验证应用服务自身资源、方法和撤权边界。两者的越权业务调用都被真实拒绝；B 的宿主原生权限另按实际能力说明，不用 MCP 授权冒充全机隔离。
6. 覆盖排队、用户补充、批准与拒绝、停止、中断、保存失败和未知结果。重复执行包括 B 宿主在响应丢失后重发、并发重发、缺少必要业务关联、同键不同输入；实际防重或拒绝生效，不具备保障的写方法不能通过准入。
7. 在一个已有项目中复用其原业务接口完成同一类闭环，确认人工功能和关联权限继续成立；青凝可以作为该真实消费者。
8. 每个列为正式支持的引擎分别通过适用的完整流程与权限要求。某个目标引擎存在缺口时，记录为尚未闭环，不能用其他引擎的通过替代。
9. B 从原有宿主连接应用服务，执行同类获准方法并取得成果；应用不用新增聊天界面，也不要求得到全部对话。用户可撤销应用服务权限，后续调用被拒绝。
10. 用另一个业务领域和纯对话或只读目标检查通用约定，无需修改核心语义，也不强制每个目标发生业务写入。
11. B 在同一宿主连接两个应用，验证用户授权的跨服务任务可完成，工具描述或结果诱导的未授权材料披露被宿主阻止；不支持此项控制时明确能力限制，不以单个应用授权代替隔离验收。

这些是产品验收出口，不表示当前已经验证。后续进入技术设计和实施时，仍需根据实际引擎、平台、存储和权限机制补齐相应集成、并发、恢复及兼容验证。
