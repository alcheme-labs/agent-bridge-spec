# 按规范接入 Agent

[English](SKILL.md) | 中文译文

本文件是英文 Skill 指引的中文译文，不作为第二个自动发现入口。按用户使用的语言回复；用户明确指定语言时优先遵循。

Skill 版本见 [VERSION](VERSION)。规范要求的唯一依据是同一仓库中的[规范正文](../../docs/general-integration-contract.md)；本文件只指导怎样使用正文，不新增接入义务。规范、Skill 和参考 SDK 分别版本化。

## 使用前

1. 找到本 Skill 的实际目录。若通过符号链接安装，先解析链接，再读取实际目录上两级的 `docs/general-integration-contract.md`。安装时须保留完整规范仓库，不能只复制本 Skill 文件夹。正文不可取得时，说明缺失并取得用户提供的同版仓库；不要凭本文件、旧摘要或 SDK 设计冒充已核对规范。
2. 读取正文的日期、版本、状态及第 1–2、11 节，确认本次接入角色和任务必需能力。A 是应用发起并管理其范围内会话；B 是原有 Agent 调用应用方法。两者分别适用，不为只接 B 的应用另建 Agent 控制服务。
3. 在用户允许联网、可运行 Python 3.9+ 时，执行 `python3 <实际 Skill 目录>/scripts/check_updates.py check`。仅在 `notify: true` 时按[更新规则](references/updates.zh-CN.md)报告。以 `notify` 决定是否展示；缓存仍可能产生到期提醒。未配置仓库、没有新版、已提醒、稍后期限未到或已忽略时保持安静。无法检查不阻断原任务，不宣称已是最新；用户明确询问更新时如实说明。没有脚本/本地状态能力时不承诺跨会话去重，不改用每次提醒或自行创建定时任务。

## 设计、实现与审查

- 按用户要求执行当前阶段：讨论给建议，审查给有据的问题，实现才改代码。这个 Skill 不额外授权发布、安装更新、调用付费模型或修改生产数据。
- 先找到真实调用入口、应用现有身份/权限、资源与方法执行端、结果保存和消费端，再映射适用条款。复用原应用和原宿主的负责方，不因使用本 Skill 强制安装参考 SDK、选择某语言、增加数据库/服务或复制青凝对象。
- 应用负责准备什么输入、哪些上游成果必需、如何判断合格、怎样分支和调度；本 Skill 检查已声明输入输出、当前授权、真实执行结果与恢复语义是否符合正文。不要把业务设计未定或实现 bug 自动升级成通用规范缺口。
- 接入说明复用项目现有文档，按正文第 11 节记录本次版本、角色、实际绑定、支持范围与证据；不为每条规则新建注册表或状态系统。
- 审查发现应指向适用条款、真实调用路径及具体反例。区分“已有规则未落实”“业务规则由应用决定”“尚未验证”和“正文确有遗漏”。声称规范缺口时，说明现有条款为何不足，避免以实现缺陷要求扩张规范。

## 验证与交付

按正文第 14 节及实际改动复用现有测试和真实入口验证。覆盖本次适用的正常路径与负例；是否写入、交互、恢复、跨服务或联网，决定对应检查是否适用，不把所有可选能力强制加给每个应用。

报告采用的正文版本、实际角色/运行组合、验证结果和剩余边界。规范声明、源码确认、真实流程通过、独立互通通过分别表达；一条路径通过不推导所有引擎或全部部署兼容。Skill 被加载或检查器执行成功，也不证明应用符合规范。
